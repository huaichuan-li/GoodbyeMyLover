## 与架构文档的对应关系

- 目标分层：`assets/publics/model/`（架构文档第 3 章四层结构）。本目录已按目标路径建立，四层迁移时无需再挪。

  食物罐头 → 「食物提高体力」；4 个外观不同的 NPC 占位 → 「多个 NPC 外观各异、靠线索辨认」。
- 场景类（病房 / 走廊 / 末日走廊 / 模块化走廊）是**布局参考**，不是最终关卡；其他组完成正式资产后替换。
- 这些是**策划侧的占位与接口**，不是人物设计交付物；不替其他组做角色设定。

## 给写码 / 资产同学的硬约束

1. **GLB 会打破现有 `file://` 双击可跑的零依赖约束**：浏览器直接打开本地 HTML 时 `fetch()` 本地 GLB 会被 CORS 拦。
   要么走 `node tools/serve.mjs` 本地服务，要么把模型内联成 base64 / 转程序化几何。接入前请按架构文档第 14 章【待确认】确认方案。
2. 本目录当前**不在** `tools/build-standalone.mjs` 的内联清单里，standalone.html 不会自动包含这些模型。
3. 单文件超过 100 MB 不能直传 GitHub；体积较大时建议 Git LFS 或让资产组自行压缩贴图（1k → 512）。
4. 面数列是 Sketchfab 原模型的三角面数，仅供性能预估；GLB 体积含贴图，下载时选的是 glb（1k 贴图档）。
5. 替换资产时保持**文件名不变**，下游 Agent 按 `manifest.json` 的 `file` 字段引用，换模型不用改代码。
